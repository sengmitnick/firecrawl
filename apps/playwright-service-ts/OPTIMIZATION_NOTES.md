# API.TS 优化说明

## 问题分析

用户反馈获取到不完整的微信公众号页面，主要表现为：
- 标题为空
- 标题显示为"微信公众平台"
- 内容不完整

## 根本原因

1. **验证元素检测延迟**：原代码先等待6秒才检测验证按钮，导致页面可能已经跳转到验证页
2. **等待时机不当**：在获取页面内容前没有等待关键元素加载完成
3. **缺少内容验证**：没有检查页面内容是否真正加载完成
4. **等待时间过长**：固定等待时间过长，影响性能

## 优化方案

### 1. 调整等待策略 (scrapePage函数)
- **缩短初始等待**：从6秒缩短为3秒
- **优先处理验证**：立即检测并处理验证元素，避免延迟
- **智能等待**：点击验证按钮后等待 `networkidle` 状态

### 2. 等待关键元素加载
新增多个微信公众号文章的关键选择器检测：
```typescript
const contentSelectors = [
  '#activity-name',           // 文章标题（新版）
  '#js_name',                 // 文章标题（旧版）
  '#js_content',              // 文章内容
  '#img-content',             // 图文消息内容
  'div.rich_media_title',     // 富媒体标题
  'div.rich_media_content'    // 富媒体内容
];
```

### 3. 内容完整性验证
新增 `validatePageContent` 函数，检查：
- 页面标题是否为空
- 标题是否为"微信公众平台"等异常值
- 是否仍存在验证元素
- 是否包含文章内容元素

### 4. 响应增强
API响应中新增字段：
- `contentValid`: 布尔值，表示内容是否有效
- `validationWarning`: 字符串，说明验证失败原因

## 优化后的流程

```
1. 导航到URL
2. 等待3秒初始加载
3. ⭐ 立即检测验证元素
4. 如果有验证元素 → 点击 → 等待networkidle → 等待3秒
5. 如果没有验证元素 → 等待3秒
6. ⭐ 等待关键内容元素出现（标题/内容）
7. 检查自定义选择器（如果有）
8. 再等待2秒确保动态内容渲染
9. 获取页面内容
10. ⭐ 验证页面标题和内容完整性
11. 返回结果（包含验证状态）
```

## 预期效果

1. **减少不完整页面**：通过等待关键元素，确保内容加载完成
2. **更快检测异常**：提前检测验证元素，避免等待超时
3. **可观测性提升**：详细日志和验证结果，便于排查问题
4. **性能优化**：减少不必要的等待时间

## 使用建议

1. 监控API响应中的 `contentValid` 字段
2. 如果 `contentValid: false`，查看 `validationWarning` 了解原因
3. 对于频繁失败的URL，可以增加 `wait_after_load` 参数
4. 使用 `check_selector` 参数指定必须存在的元素

## 兼容性

- 完全向后兼容现有API调用
- 新增的字段为可选字段，不影响现有客户端
